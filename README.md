# Express 37 Signals

Telegram-бот на Python для завершённых раундов «Экспресс 37». Он получает число `0`–`36` из игрового WebSocket BetBoom, ведёт пять независимых счётчиков невыпадения и отправляет сигнал при точном достижении порога группы. Браузер и аккаунт BetBoom не требуются.

## Запуск

Нужен Python 3.10+ и доступ к Telegram и BetBoom.

Windows:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

В `.env` поместите `TELEGRAM_BOT_TOKEN=...`. Существующий ключ `BOT_TOKEN` тоже поддерживается. Пример — [.env.example](.env.example). Токен не выводится в логи. После запуска откройте своего бота и отправьте `/start`; `chat_id` сохранится автоматически.

Команды:

- `/start` — включить уведомления; повторный вызов не создаёт дубль подписки.
- `/stop` — отключить уведомления.
- `/status` — последние пять чисел, все счётчики, статус WebSocket и время последнего раунда (UTC).

Группы, названия, числа, отдельный порог каждой группы и количество чисел в сообщении задаются в [config.json](config.json). По умолчанию порог равен 5 для всех групп. После изменения конфигурации перезапустите процесс.

## Как работают сигналы

Если число входит в группу, её счётчик сбрасывается в ноль. Иначе прибавляется единица. Число `0` даёт промах всем группам. При точном достижении порога отправляется одно сообщение каждому активному подписчику. Следующий сигнал для этой группы возможен после попадания и новой серии промахов.

Первый снимок WebSocket задаёт начальный ID и не считается новым раундом. Раунды с тем же или меньшим ID игнорируются. После рестарта состояние восстанавливается из `express37.sqlite3`. Если в WebSocket истории есть сохранённый раунд с тем же числом, программа сопоставляет историю с ID и восстанавливает пропущенные числа и счётчики. Уведомления за время простоя не отправляются задним числом. Когда история слишком коротка или не совпадает с сохранённым раундом, счётчики помечаются неизвестными до попадания в соответствующую группу.

Раунд, счётчики и задания на отправку сохраняются в SQLite одной транзакцией. Перед отправкой задание помечается как попытка. Поэтому перезапуск не повторит уже начатую отправку. Если соединение оборвётся во время запроса к Telegram, результат может быть неизвестен; такое задание автоматически не повторяется, чтобы избежать дублирующего сообщения. Статусы `sent`, `failed`, `attempted` хранятся в таблице `notifications`.

В логах видны подключение и переподключение WebSocket, ID и число раунда, задержка от `dttm_end`, счётчики, сигналы и результат отправки. Задержка использует часы компьютера и сервера, поэтому VPS должен синхронизировать время.

## Проверка

```bash
python -m pytest -q -p no:cacheprovider
```

Для проверки реальной доставки запустите `python main.py`, отправьте боту `/start`, затем дождитесь обычного сигнала. Можно временно уменьшить `threshold` у одной группы, перезапустить процесс и вернуть `5` после получения сообщения. Уже накопленные счётчики сохраняют своё значение; для чистого теста используйте отдельную временную SQLite-базу.

4 октября 2026 года живой WebSocket отдал завершённые раунды с задержкой около двух секунд. Это короткая проверка, а не гарантия постоянной задержки: игровой протокол внутренний и может измениться. [Страница игры BetBoom](https://betboom.ru/game/tennis37_v2) указывает nardsleag.am как официальный источник результатов.
